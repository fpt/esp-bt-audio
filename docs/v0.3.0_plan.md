# v0.3.0 改版計画

v0.2.0（JLCPCB Economic PCBA）の実機確認と対照試験の結果を受けて、v0.3.0 では i2s-power 基板のオーディオ部（PT8211 ＋ LM4881）を TAD5142（DAC ＋ ヘッドホンドライバ）1 個に置き換える。
v0.2.0 の経緯・試験の詳細は `v0.2.0_conclusion.md` を参照。

## 1. v0.2.0 からわかったこと

| 項目 | 結果 |
|---|---|
| 起動・電源ラッチ・書き込み・Bluetooth・A2DP・LED | OK |
| Bluetooth 動作中の「ジー」というノイズ（約 100Hz ＋ 高調波） | **LM4881 の段から入る**（下の対照試験） |
| iPhone の音量を下げたときの歪み | 主に一定の大きさのノイズが小さな音に重なったもの（UDA1334A → LM4881 でも同じ） |
| ソフトウェア（音声データ、I2S の送り方） | 原因ではない（全サンプル 0 でもノイズは同じ） |

対照試験（2026-11-14、`v0.2.0_conclusion.md` 4 章）。ESP32・main 基板・i2s-power 基板の 3V3・I2S の配線は共通。

| 構成 | DAC | アンプ | ノイズ |
|---|---|---|---|
| T1 | PT8211 | LM4881 | あり |
| T2 | UDA1334A モジュール | なし（モジュールのジャックでイヤホンを直接駆動） | **なし**。とてもきれい（最大音量で少し歪む） |
| T3 | UDA1334A モジュール | LM4881 | あり |

- T2 がきれいなので、main 基板・ESP32・無線・3V3 レール・I2S は主な原因ではない
- T2 と T3 の差は LM4881 の経路だけ。BYPASS に 10µF を足しても少ししか減らない（B2）ので、主な経路は LM4881・出力の 470µF・ジャックの GND 側と考えられる
- DAC だけを替えてもノイズは消えない。**DAC とヘッドホンアンプの両方を替える**

## 2. v0.3.0 のオーディオ部: TAD5142

```
ESP32 ── I2S（BCK / WS / DIN）──► TAD5142 ── OUT1P（L）/ OUT2P（R）──► ジャック
                                     └──── OUT1M（共通 1.65V）──► スリーブ（OUT2M でセンス）
```

TI TAD5142（データシート SLASF32A）。注文型番 TAD5142IRGER、VQFN-24（4mm × 4mm、0.5mm ピッチ、サーマルパッド付き）。

### 2.1 選んだ理由

| 項目 | 内容 |
|---|---|
| 設定 | ピン（MD0〜MD6）だけで設定する。I2C・SPI は不要で、main 基板とヘッダは変えなくてよい |
| クロック | ターゲットモードで BCLK・FSYNC から内部 PLL で動く（MCLK 不要、自動検出）。44.1kHz・BCLK 64fs（2.8224MHz）に対応 |
| ヘッドホン出力 | 擬似差動（外部コモンモードセンス）。16Ω に 62.5mW、フルスケール 1Vrms（AVDD 3.3V）。出力コンデンサも BYPASS（VDD/2）もない |
| 性能 | ヘッドホン出力のダイナミックレンジ 107dB、PSRR 110dB（AVDD、1kHz） |
| 電源 | AVDD 3.0〜3.6V、IOVDD 3.3V。単電源で動く（DREG は内部レギュレータ） |
| 電流 | 再生中 約 20mA（48kHz、ヘッドホン）、クロック停止中（スリープ）AVDD 0.8mA |

- v0.2.0 のノイズの主な経路（アンプ・出力コンデンサ・ジャックの GND）は、スリーブを TAD5142 が駆動するのでイヤホンの戻りに乗らない
- DAC とアンプが 1 チップなので、部品点数が減り、アナログの配線も短くなる

### 2.2 ピン設定

| ピン | 接続 | 設定 |
|---|---|---|
| MD0 | VSS に直結 | ターゲット、I2S |
| MD2, MD1 | Low, Low | AVDD 3.3V、32 ビット、線形位相フィルタ |
| MD3 | VSS（ターゲットモードではグラウンドに直結） | — |
| MD5, MD4 | High, High | 擬似差動、ヘッドホン専用 |
| MD6 | Low | ステレオ |
| GPO | 未接続（テストパッド） | クロックエラーの割り込み（ラッチ、電源の再投入で解除） |

- MD1〜MD6 は IOVDD または VSS に、MD0 は AVDD または VSS につなぐ（MD0 は抵抗の値でモードが変わる多値入力。今回は直結）
- 16 ビットは選べない（24 か 32 ビット）。ファームウェアで 32 ビットスロットにする（3 章）

### 2.3 ジャック

- L = OUT1P、R = OUT2P、スリーブ = OUT1M（両チャンネル共通のコモンモード、DC 1.65V）
- OUT2M はコモンモードのセンス。ジャックのスリーブ端子の近くで OUT1M の配線につなぐ
- **スリーブは GND につながない。** ジャックのスイッチ端子・シェルも GND から切り離す
- スリーブに DC 1.65V が出るので、イヤホン・ヘッドホン専用になる（スリーブが GND の機器のライン入力につなぐとコモンモードが GND に短絡する）
- アナログのゲイン設定はない。iPhone の音量を最大にすると大きすぎる場合は、ファームウェアで最大音量を制限する（DR 107dB なのでデジタルで絞っても問題になりにくい）

### 2.4 電源

| ピン | 接続 |
|---|---|
| AVDD | 3V3 からフェライトビーズ、10µF ＋ 0.1µF |
| IOVDD | 3V3、10µF ＋ 0.1µF |
| VREF | 1µF 以上を VSS へ直接（負荷をつけない） |
| DREG | データシートの図 7-1 に従ったコンデンサ（回路図作成時に値を確認） |

- PSRR が高いので、v0.2.0 計画にあったアナログ専用 LDO はやめる。全負荷を RT9080 の出力から取る方針も変えない（電源オフ時に µA 程度）
- 電源の立ち上がりは 0.1V/µs より遅くする必要がある。RT9080 の起動時間をデータシートで確認する（足りなければ RT9080 の出力容量で調整）
- 電源オン後 2ms 以上たってからクロックを入れる（ESP32 の起動で満たされる）。電源を切る前にクロックを 10ms 以上止める（3 章）。電源オフから再投入まで 100ms 以上あける

### 2.5 GND と配置

- サーマルパッドをビアで GND プレーンにつなぎ、IC の下を GND の中心にする。VSS と VSSA は同じ GND
- パスコンは各ピンの直近、VREF のコンデンサの GND は VSS ピンへ直接
- OUTxx の近くに BCLK などのクロックを通さない。デジタルとアナログの配線を交差させない
- ESP32 の電流ループ（RT9080 → ヘッダ 3V3 → ESP32 → ヘッダ GND → RT9080 の GND）が TAD5142 とジャックの下を通らない配置にする
- ヘッダの NC ピン（8〜10）を GND に割り当て、GND のインピーダンスを下げる
- RT9080 の出力の C13（1µF）を 10µF に増やす

### 2.6 その他

- main 基板と ESP32 の GPIO（BCK 26、WS 25、DATA 27）は変えない。ヘッダの信号も同じ（MCLK のピンは使わない）
- TAD5142 には EN ピンがない（クロックの有無で自動的にスリープ・復帰する）。GPIO23（旧 SHUTDOWN）はヘッダに残し、i2s-power 側は未接続（テストパッド）にする
- TAD5142 は PCBA で実装する（VQFN の手はんだはしない）。部品番号は発注前に `lcsc-check` で確認する

## 3. ファームウェア

| 項目 | 内容 | 状態 |
|---|---|---|
| DAC の形式 | Kconfig に TAD5142 を追加。Philips I2S、32 ビットスロット（BCK = 64fs）、16 ビットのサンプルを上位 16 ビットに置く | 未対応 |
| アンプの ON / OFF | EN の代わりに I2S のクロックを止める（`i2s_channel_disable`）。再生開始で再開し、停止後 `CONFIG_BTR_AMP_OFF_DELAY_MS` で止める | 未対応 |
| 電源オフ | GPIO15 を落とす前に I2S を止め、100ms 以上待つ（TAD5142 の音量ランプダウン・停止のため） | 未対応 |
| サンプルレートの変更 | 今の `apply_rate` は I2S を止めて再開する。TAD5142 がクロックを再検出して復帰するかを実機で確認する | 未確認 |
| 最大音量 | 大きすぎる場合に Kconfig で上限を設ける | 必要なら |
| L/R の順 | 標準 I2S で L が先。テストトーン（`CONFIG_BTR_TEST_TONE`）で確認する | 未確認 |
| 送信電力の制限（-6dBm） | v0.3.0 でノイズが消えたことを確認したら外す（通信距離のため） | 暫定で有効 |
| アンダーランのカウント | `10 s:` のログに出す。動作確認が済んだら残すか決める | 済 |

## 4. 発注前の確認

1. TAD5142IRGER を JLCPCB で実装できるか。LCSC では見つかっていない（2026-11-14 時点。TAC5142IRGER C43656746 は I2C 制御の別品なので不可）。JLCPCB のグローバル調達・部品の持ち込みと、それが Economic PCBA で使えるかを確認する
2. RT9080 の起動時の立ち上がり速度（2.4）
3. ジャックの品番を選び、スリーブ・スイッチ・シェルが GND から独立していることを確認する
4. 回路図 → ERC / DRC → `lcsc-check` → 発注

## 5. 未確認の項目

- WS2812B-V6 の色順
- 電池電圧の ADC 精度
- クロックの開始・停止時のポップ音（TAD5142 は停止時に音量をランプダウンする）
- 1Vrms フルスケールでのイヤホンの音量（iPhone の音量最大付近で使えるか）
- 44.1kHz ⇔ 48kHz の切り替え時の復帰
